# Команди наставника — як користуватися

Команди лежать у `.claude/commands/`. Викликаються в Claude Code через `/назва`,
все після назви — аргументи (необов'язкові, якщо не сказано інше).
Нові або змінені команди підхоплюються після перезапуску `claude`.

Типовий порядок у сесії: `/start` → робота (`/hint`, `/explain`) → `/check` → `/end-session`.

---

## `/start [тема]` — початок сесії

Читає «Поточний стан» з `LEARNING_LOG.md`, нагадує, де ти зупинився,
ставить одне питання на повторення по слабкій темі і питає план на сьогодні.

```
/start
/start Unit 1 — що таке tools в агентах
```

**Порада:** відповідай на питання на повторення сам, навіть якщо не впевнений —
це і є тренування.

---

## `/hint [файл або опис]` — підказка без рішення

Дає **одну** підказку за драбиною і позначає рівень «Підказка N/4»:
1. навідне питання → 2. концепція / документація → 3. фрагмент коду → 4. рішення.
Кожен повторний `/hint` по тій самій вправі — на сходинку вище.

```
/hint 3110/02.py не розумію, що повертає pipeline
/hint чому мій async код виконується послідовно?
/hint
```

Повне рішення — тільки якщо прямо написати: `покажи рішення`.

**Порада:** після кожної підказки спробуй сам хоча б 5–10 хвилин.

---

## `/check <файл> [що перевірити]` — рев'ю твого рішення

Читає файл (не змінює і не запускає) і відповідає у форматі:
✅ що правильно → ❌ помилки і чому → ⚠️ пастки Python → 💡 покращення,
інколи 🧠 просить пояснити свій код своїми словами.

```
/check 3010/01.py
/check 3110/02.py особливо type hints
/check 3110/agent.py чи правильно я використовую async
```

**Порада:** виправив — запусти `/check` ще раз на тому ж файлі.

---

## `/explain <концепція>` — пояснення концепції

Суть, аналогія з PHP/Magento або TypeScript (і де вона ламається), міні-приклад,
типова пастка, посилання на документацію і питання для самоперевірки.

```
/explain генератори і yield
/explain декоратори
/explain tokenizer в transformers
/explain різниця між list і tuple
```

**Порада:** питай про концепцію загалом, а не «поясни мою вправу» — для вправи є `/hint`.

---

## `/end-session [нотатки]` — завершення сесії

Складає чернетку підсумку (що пройшли, помилки, до якої сходинки підказок дійшов,
що повторити), показує її і **тільки після твого підтвердження** оновлює `LEARNING_LOG.md`.

```
/end-session
/end-session досі плутаюсь у різниці між model і tokenizer
```

**Порада:** перед підтвердженням допиши те, що сам вважаєш слабким місцем —
журнал корисний настільки, наскільки чесний.

---

## Без команд

Звичайні повідомлення теж працюють — правила наставника з `CLAUDE.md` діють завжди.
Корисні фрази:
- `покажи рішення` — зняти обмеження на повне рішення для поточної вправи;
- `можеш змінити файл X` — дозвіл редагувати твій файл;
- `запусти` — дозвіл запустити запропоновану команду.
